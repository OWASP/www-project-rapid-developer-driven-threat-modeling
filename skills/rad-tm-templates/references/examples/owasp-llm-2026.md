# OWASP LLM Applications 2026 Threat Template

- **Context:** implementation
- **Scope:** Features that embed an LLM as an application component (chat, RAG, tool/function calling, generated content or code) — developer-addressable threats derived from the OWASP Top 10 for LLM Applications 2026. Autonomous agents (persistent memory, multi-agent, long-running autonomy) → pair with an OWASP Agentic Top 10 template.
- **Maintainer:** Security team (TBD)  **Version:** v1 (draft)  **Reviewed:** pending — security-expert review required before production use
- **Source & licence:** Adapted from *OWASP Top 10 for LLM Applications 2026* (genai.owasp.org, pre-publication copy dated 2026-08-04), CC BY-SA 4.0. This template is a derivative work and is shared under CC BY-SA 4.0. OWASP entry references are given in each description; template IDs are independent of OWASP ranking so they stay stable when the list is re-ordered.

| ID | Threat | Description | Default severity | Suggested controls |
|----|--------|-------------|------------------|--------------------|
| GAI-01 | Direct prompt injection overrides app instructions | A user's message overrides the system prompt's role and limits, making the model disclose, generate, or act outside the feature's intended scope (LLM01:2026). | High | State scope as explicit allow/deny rules in the system prompt (partial control only); keep credentials and authorization decisions in application code, never in the prompt; validate every response against a strict output schema in code before anything acts on it; red-team with testers who know the deployed defenses before release |
| GAI-02 | Indirect prompt injection via ingested content | Instructions hidden in content the model reads — web pages, emails, documents, tickets, issue titles, tool or MCP output, images, audio — hijack the model, which then acts with the user's privileges (LLM01:2026). | High | Treat all retrieved, tool and uploaded content as untrusted, including internal channels outsiders can write to (forms, tickets, issues); pass external content in a separate, source-labelled channel; apply the Rule of Two — no flow combines untrusted input, sensitive data and external communication/state change without per-action human approval; OCR/transcribe non-text inputs and run the same filters on the extracted text |
| GAI-03 | Invisible-Unicode instruction smuggling or exfiltration | Tag-block, variation-selector or zero-width characters hide instructions in input, or smuggle data out in output that looks benign when rendered (LLM01:2026). | Moderate | Strip U+E0000–U+E007F, U+FE00–U+FE0F, U+200B–U+200D and U+2060 at every ingest and render boundary; apply the same normalization before embedding (see GAI-14); show approvers the exact action payload, not a model-written summary |
| GAI-04 | Retrieval returns content the user isn't authorized to see | RAG or similarity search runs across the whole index and filters afterwards (or not at all), so the model receives — and can repeat — chunks belonging to other users, tenants or restricted documents (LLM02:2026, LLM09:2026). | High | Enforce authorization inside the index query at document and chunk level, not after retrieval; derive tenant/user scope server-side, never from client input; use separate indexes per tenant or trust zone for high-sensitivity data; authenticate and rate-limit embedding and search endpoints like any other API |
| GAI-05 | Sensitive data over-shared into context, output or provider | The feature sends more personal or confidential data to the model or an external provider than the task needs, and the model echoes it back or the provider retains or trains on it (LLM02:2026). | High | Send only task-required fields (no auto-append of full customer records); scrub PII at ingest; filter output with pattern matching plus NER/trained classifiers, not regex alone; use provider settings and contract terms that technically disable training and retention; per-user and per-session query budgets on sensitive endpoints |
| GAI-06 | Prompts, completions or reasoning traces leak via logs and shares | Observability tools, logs, traces or shareable conversation links store full prompts, retrieved chunks, tool arguments and reasoning traces where unauthorized people or search engines can reach them (LLM02:2026). | Moderate | Redact prompts, completions and traces before they reach APM/observability platforms; restrict access to LLM logs to the same audience as the source data; classify and redact reasoning traces and tool arguments as output; set noindex and access control on shared-conversation URLs |
| GAI-07 | Fine-tuned model memorizes and regurgitates training data | Sensitive records used to fine-tune a model or adapter can be extracted via crafted prompts or membership inference after deployment, and stay extractable even after the source is deleted (LLM02:2026). | Moderate | Scrub PII and deduplicate datasets before fine-tuning; don't expose log-probabilities or confidence scores on production endpoints; per-user query budgets and probing detection; run extraction and membership-inference tests as a release gate for fine-tuned models |
| GAI-08 | Tools grant more functionality or permission than needed | The model can call tools or credentials that do more than intended (delete as well as read, run any shell command, write to any table), so any manipulated output becomes a damaging action (LLM03:2026). | High | Offer only the tools the feature needs and remove trial/unused ones; replace open-ended tools (shell, fetch-any-URL) with purpose-built tools whose parameters are schema-validated in code; give each tool's downstream identity least privilege (e.g. SELECT on one table only) |
| GAI-09 | Tools act with a shared service identity instead of the user's | Downstream calls use a privileged generic account, so the model can reach data and actions the current user could not — including through chained tool or sub-agent calls (LLM03:2026). | High | Execute tool calls in the end user's context via OAuth with minimal scopes; propagate the original user's authorization across chained/delegated calls; enforce authorization in a deterministic policy check before every downstream call, never by asking the model |
| GAI-10 | High-impact action executes without human confirmation | The model triggers irreversible, financial or externally visible actions (send, post, delete, pay) with no independent approval step (LLM03:2026, LLM01:2026). | High | Require explicit user approval for irreversible or external actions, showing the exact rendered action; graduated policy — auto-approve reversible/low-value actions, block or escalate irreversible/high-value ones; log all tool invocations; circuit breakers on invocation count and cumulative parameter value |
| GAI-11 | Hallucinated or vulnerable dependencies and LLM serving components | Attackers register package names that coding assistants hallucinate ("slopsquatting"), or exploit outdated or exposed LLM frameworks and inference servers (e.g. vLLM, Ollama, Ray) (LLM04:2026, LLM06:2026). | High | Verify every AI-suggested dependency exists and is the intended package before adding it; SCA scanning and patch cadence covering LLM libraries and serving frameworks; pin versions with lockfile hashes; require authentication on all inference endpoints and never expose them publicly; disable unsafe deserialization and special-token passthrough in serving config |
| GAI-12 | Unverified or tampered model, adapter or inference artifact | A model, LoRA adapter, quantized build, chat template or tokenizer config from a hub or pipeline is backdoored, swapped, or executes code on load — including via namespace reuse or a mutable "latest" reference (LLM04:2026, LLM05:2026). | High | Reference models and adapters by immutable digest, never by name or tag alone; verify signatures (e.g. OpenSSF Model Signing / Sigstore) and hashes before promotion; use safetensors and never load pickle files from untrusted sources; treat model scanners and safe-loader flags as defense-in-depth only and keep loaders patched; record models, adapters, datasets and licences in an AI-BOM (e.g. CycloneDX ML-BOM) |
| GAI-13 | Poisoned fine-tuning or feedback-loop data | Attacker-contributed or contaminated training, fine-tuning or user-feedback data plants backdoors, bias or eroded refusals that pass normal evaluation (LLM05:2026). | Moderate | Fine-tune only on curated, provenance-tracked datasets under version control (e.g. DVC) so you can roll back; validate incoming data and vet third-party datasets; require human review and rate limits before user feedback feeds retraining; run trigger/backdoor probing after every fine-tune |
| GAI-14 | Attacker-writable content poisons or jams the RAG corpus | Content arriving via scraping, uploads or partner feeds is crafted to be retrieved for target queries, steering answers with false information or making the model refuse to answer (LLM09:2026, LLM05:2026). | High | Keep content of different trust levels in separate indexes; record provenance (source, ingest time, trust tier, pipeline version) per embedding so bad batches can be purged; normalize text before embedding (strip zero-width characters, hidden text, homoglyphs); human review for external content entering sensitive indexes; alert on new vectors that rank highly for many unrelated queries |
| GAI-15 | Embeddings and vector stores treated as non-sensitive | Exported, backed-up or third-party-hosted embeddings can be inverted to recover source text, and raw similarity scores reveal whether a specific document exists (LLM09:2026). | Moderate | Classify vector stores and their backups at the same tier as the source documents; encrypt embeddings at rest with separately managed keys; delete embeddings when source documents are deleted and reconcile regularly; don't return raw similarity scores to clients; treat embedding-API keys as secrets |
| GAI-16 | Unbounded token, cost or agent-loop consumption | Large inputs, long reasoning, expensive multimodal requests or recursive tool loops exhaust capacity or budget ("denial of wallet"), or high-volume querying harvests outputs to clone the model (LLM06:2026). | Moderate | Quotas on tokens per minute/day and estimated cost per user and API key, with pre-flight token estimation; per-request limits on output and thinking tokens; hard spending caps that halt inference rather than just alert; step, recursion-depth, time and per-run cost limits on agent runs; don't expose log-probabilities |
| GAI-17 | Ungrounded model output drives a decision or action | A hallucinated, stale or incomplete answer — a wrongly inferred state, an omitted constraint, a fabricated citation — is acted on as fact by a user or the system (LLM07:2026). | Moderate | Separate generation from execution (claim-check-act) and verify claims against authoritative, current sources before acting; validate tool-call arguments, preconditions and current system state in code; require structured outputs with mandatory fields to surface omissions; label unverified content and show sources in the UI |
| GAI-18 | Secrets or security rules placed in the system prompt | Credentials, tool schemas, role requirements or refusal/authorization rules in hidden context are extracted, handing attackers keys or a map for bypass (LLM08:2026). | High | Never put credentials, tokens or security-critical config in prompts or tool descriptions — assume all context is user-visible; enforce authorization and content policy in deterministic systems outside the model; split tasks needing different privileges into separate authorization contexts |
| GAI-19 | Model output reaches an interpreter sink unvalidated | Output is passed to a shell, eval, SQL query, file path, HTML/JS/Markdown renderer, email template or terminal, causing RCE, injection, XSS, path traversal or terminal-escape abuse (LLM10:2026). | High | Treat model output as untrusted user input; parameterized queries for any LLM-derived SQL; context-aware output encoding plus a strict CSP; never pass output to exec/eval — run required generated code in an isolated sandbox; strip ANSI/OSC and other control characters before writing to terminals or logs; SAST and review on generated code before it ships |
| GAI-20 | Data exfiltration via auto-rendered images and links | Injected output includes a Markdown image, link preview or iframe whose URL carries conversation data to an attacker's server the moment the client renders it (LLM10:2026, LLM01:2026). | High | Disable auto-rendering of Markdown images, link previews and iframes by default; where rendering is needed, allowlist origins or proxy fetches server-side and strip query parameters; enforce CSP img-src/connect-src allowlists in chat UIs |
